# textdesk

локальный веб-просмотрщик/редактор текстовых файлов: открывается в браузере,
Ctrl+S пишет правки прямо на диск, снаружи корня сервера — только чтение.

## файлы
- gen.py — сборка index.html из текстового файла: `python3 gen.py [вход.txt] [выход.html]`
- serve.py — сервер на 127.0.0.1: статика + запись: `python3 serve.py [порт] [корень]`
- test_viewer.py — дымовой тест (playwright + системный chrome): `python3 test_viewer.py`
- hljs.min.js — вендоренный highlight.js (BSD-3), не генерится

## правила
- index.html — сгенерённый артефакт: руками не править, только через gen.py
- после правки gen.py: `python3 gen.py && python3 test_viewer.py`
- интерфейс в px, масштабируется только текст (книжный режим масштабирует колонку чтения)
- книжный режим читается только с переносом: applyWrap внутри книги принудительно включает soft wrap, кнопка переноса скрыта, выход возвращает прежнюю настройку; продолжения перенесённых строк сдвинуты на 2ch (висячий отступ), первая строка логической строки — у гаттера
- страница книги — фиксированные N строк экрана: шаг страницы = N × pitch, где pitch = round(размер шрифта × --book-lh-ratio), и все строки холста кратны pitch (line-height книги = --book-lhp, min-height строки = 1lh). поэтому граница страницы всегда попадает на границу строки экрана и половинчатых строк нет; страница может начаться с продолжения логической строки — это нормально для читалки, номер у неё не показывается. если шрифт даст line box выше pitch, сетка поедет — тогда pitch = max(round(размер × ratio), высота строки шрифта)
- в книге статус показывает первую видимую строку (lineAtY от scrollTop), а не каретку: каретки там нет
- #backw — окно обрезки холста: #back внутри него ездит трансформом. в книге окно совпадает с полем textarea (left/right/top/bottom = --bpx/--bpy), поэтому соседняя строка не подглядывает в поля карточки, а ширина окна + 2ch компенсирует висячий отступ, чтобы перенос совпадал с textarea и высоты не разъезжались
- hljs: подсветка по вьюпортному окну, цвета токенов — переменные --tok-* в обеих темах
- запись — только внутрь корня, текстовые расширения из ALLOWED_EXT/ALLOWED_NAMES, Origin сверяется; сам POST пишет через временный файл в той же папке + os.replace (fsync, права и владелец переносятся), чтобы обрыв не оставил обрубок
- просмотр markdown: markdown-it с `html:false` (сырой html не исполняется, `javascript:` у ссылок отбрасывается самим парсером), внешним ссылкам ставится target=_blank; рендер только в #view, редактор в этом режиме скрыт, книга всегда показывает исходник; имена — #viewbtn, body.preview
- перенос — только про чтение: авто-решение не сохраняется в st.wrap (пересчитывается на каждый файл: код без переноса, текст с переносом, а код со строкой длиннее 2000 символов — как минифицированная простыня — всё равно с переносом), явное нажатие кнопки сохраняется и сильнее эвристики; при выключенном переносе textarea тоже white-space:pre, иначе её высоты разъезжаются с холстом и низ файла теряется
- вендоренные файлы (hljs.min.js, mdit.min.js) serve.py отдаёт из папки приложения по фиксированному списку VENDORED, а не из корня сервера
- навигатор: ответы /__tree и /__dir защищены счётчиком navSeq — устаревший ответ не перетирает свежий список
- палитра взята из radix colors (мит), роли по их шкале: фон 1-3, поверхности 4-5, границы 6, текст 11-12; тёмная = sand-dark 1/3/4/6/11/12 + amber/violet/grass/blue/teal/red-dark-11; светлая = sand 1/3/4/6/11/12, а токены и акцент — микс шага 11 с 12 на 30% (шаг 11 рассчитан на белый фон, на sand-3 даёт меньше 4.5); в тестах есть wcag-проверка обеих тем (текст AAA ≥7, токены и подписи ≥4.5, чистый белый и чёрный запрещены)
- шкала отступов 4/8/12/16/24 (--s1..--s5) и радиусы 6/8/10 (--r1..--r3): у кнопок, полей, бара и панели обзора размеры только из этих токенов, произвольные 5/7/11px не заводить
- иконки не рисуем руками: берём готовый путь из Lucide (ISC) или из Rune Icons (уже в спрайте), вставляем символом 24x24 со stroke-width 2; новая иконка — только если она ускоряет скан (поиск, настройки, удаление, статус), не для украшения. сейчас из lucide: folder-tree (файлы), search (поиск)
- тени только через токены --shadow-card и --shadow-pop (взяты из primer/github: floating-small и floating-large без кольца, светлая и тёмная свои); самодельные rgba(0,0,0,.3+) в правилах запрещены
- сохранение показывает «сохраняю…» и блокирует кнопку, пока идёт POST; уход из файла с несохранёнными правками проходит через confirmLeave (openServerFile, openAbsFile, локальный инпут)
- локальный файл: pickLocal() сначала пробует showOpenFilePicker (File System Access API), и тогда Ctrl+S пишет через createWritable прямо в файл, сервер не участвует; фолбэк — input type=file, где цель записи подключается по имени, а при неоднозначном имени файл открывается только на чтение (имена не угадываем). статус в обоих случаях говорит, куда пойдёт запись
- права локального файла просим по минимуму: возврат после F5 — только чтение (queryPermission/requestPermission mode read, по кнопке в карточке пустой зоны, где написано имя файла), запись — лениво на сохранении (createWritable ловит NotAllowedError, только тогда requestPermission readwrite). «открыть файл…» всегда открывает пикер и никогда не выпрашивает доступ к прошлому файлу
- статусные сообщения в #target ходят только через setStatus() со сбросом предыдущего таймера, иначе таймер прошлого действия затирает свежее сообщение
- пустая рабочая зона не бывает молча серой: body.hint + .hintcard показывают «файл не открыт» с дорогой к началу (Ctrl+P / открыть файл…) или текст ошибки загрузки; карточка живёт в #view, отдельных слоёв не заводить. редкие действия в баре (копировать всё) — только иконка с title, метка всплывает лишь в состоянии .ok
- empty state у обзора свой в каждой ситуации: пустая папка (подсказка + Backspace), фильтр по имени без совпадений (Enter откроет это как путь, Esc сбросит), поиск по корню без совпадений (сколько файлов просканировано, Esc назад); строка «пусто» не используется, /__grep возвращает scanned
- любая однострочная подпись, которую может раздуть контент (имя файла, строка в результатах), обязана иметь ellipsis и title с полным значением
- загрузка файла: ?file= главнее памяти (st.file), у загрузок счётчик loadToken — устаревший ответ не применяется; ошибка чтения видна в #target (loadError) и не стирается, пустое поле без объяснения запрещено
- поиск: подсветка только через CSS Highlight API (Ranges по текстовым узлам #back), DOM строк не трогаем — сетка и hljs не ломаются; перерисовывать после buildBack/highlightView/скролла (scheduleFindPaint), диапазоны ограничены окном вьюпорта, счётчик знает общее число
- /__grep: q (минимум 2 символа), case=1, лимиты — файл до MAX_VIEW, 8 строк на файл, 120 совпадений, 40 файлов; регистр берётся из флага Aa в панели поиска; клик по результату открывает файл и ставит его на строку через pendingFind
- клавиатура обзора: набор текста и Backspace фильтруют дерево только когда фокус не в поле ввода (в поле свои клавиши, Enter не активирует выбранный пункт списка); Ctrl+Shift+F открывает обзор с фокусом в поиске по корню, Ctrl+F — поиск по файлу, F3 — следующее
